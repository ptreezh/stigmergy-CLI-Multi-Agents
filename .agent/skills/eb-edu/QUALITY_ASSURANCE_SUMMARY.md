## 🎯 质量标准

### CLI 命令质量标准

每个 CLI 命令必须满足：

- ✅ **Shebang 声明** - `#!/usr/bin/env node`
- ✅ **帮助信息** - `--help` 参数支持
- ✅ **参数解析** - 使用 args 解析
- ✅ **错误处理** - try-catch + 有意义的错误信息
- ✅ **API 调用** - 正确的 API 路径和方法
- ✅ **输出格式** - JSON 或格式化文本
- ✅ **退出码** - 成功 0，失败 1

### Skill 质量标准

每个 Skill 必须满足：

**skill.json**:
- ✅ name（小写 + 连字符）
- ✅ version（语义化）
- ✅ description（清晰简洁）
- ✅ author（作者/团队）
- ✅ category（类别）
- ✅ tags（至少 1 个标签）
- ✅ triggers（keywords + patterns）
- ✅ parameters（完整 JSON Schema）
- ✅ execution（runtime, script, timeout）
- ✅ permissions（roles, requires_auth）
- ✅ examples（至少 3 个，含 output）
- ✅ errors（错误定义，含 solution）
- ✅ help（short + long）
- ✅ business_context（concept + use_cases + best_practices）

**skill.py**:
- ✅ Shebang 声明
- ✅ 文档字符串
- ✅ build_command 函数
- ✅ execute_command 函数
- ✅ format_output 函数
- ✅ main 函数
- ✅ 错误处理

### 渐进式披露标准

每个 Skill 必须满足：

- ✅ **参数分层** - 基础参数、高级参数、专家参数
- ✅ **示例分级** - 入门级、进阶级、专家级
- ✅ **输出分层** - 核心信息、详细信息、学习入口
- ✅ **错误三层** - 简单提示、详细解释、解决方案

### LLM 可调用性标准

每个 Skill 必须满足：

- ✅ **触发词清晰** - keywords + patterns 覆盖多种表达
- ✅ **参数描述详细** - 含格式说明、枚举值说明
- ✅ **示例丰富** - 至少 3 个示例，覆盖常用场景
- ✅ **业务背景完整** - concept + use_cases + best_practices
